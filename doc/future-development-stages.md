## 0. 決策摘要與閱讀入口

建議將 Janus 定位為「圍繞本人持股與觀察股，保留研究理由、比較新舊證據、串接四模型與個人曝險的研究工作台」。成熟看盤、到價通知與通用回測功能可借助既有工具；Janus 的開發資源優先放在跨資料與個人研究脈絡的整合。

評估結論：**ACCEPTABLE WITH GUARDRAILS**。採既有系統漸進延伸，五個發布階段各自從設計走到上線後停止，不把所有候選累積成一次大發布。

| 建議順序／暫定規劃 ID | 可獨立交付的產品 | 優先級 | 啟動條件 |
|---|---|---|---|
| 基礎版：既有 SEQ-01～08 | 批次、快照、備份、四模型、估值卡、報告與 UI | 現行優先 | 依唯一 TODO 接續 |
| PLAN-01 | 研究追蹤：本人假設、證據、待確認事項與報告變化串接 | P1 | SEQ-08 有界結案；使用者指定啟動 |
| PLAN-02 | 私人曝險與唯讀交易情境 | P1 | PLAN-01 完成後；完整估值與現金契約可用 |

## 4. 效益優先評分

分數為本輪規劃判斷，**不是已量測 ROI、獲利率或研究準確率**。每個構面1～5分，越高越有利；加權總分 = 6×直接幫助 I + 5×既有重用 R + 4×差異價值 D + 3×容易交付 E + 2×低維運負擔 O，最高100。

| 候選增量 | I | R | D | E | O | 分數 | 決策理由 |
|---|---:|---:|---:|---:|---:|---:|---|
| 本人假設／筆記與事實、報告差異串接 | 5 | 5 | 4 | 4 | 5 | 93 | 重用度高，減少每次重新理解個股 |
| 私人曝險與唯讀情境 | 5 | 4 | 4 | 3 | 4 | 83 | 把既有持股、現金變成可比較情境 |
| 有界研究資料整理 | 4 | 5 | 3 | 3 | 4 | 78 | 是模型改善的支援工項，不獨立建平台 |
| 四模型研究改善 | 5 | 4 | 4 | 2 | 3 | 78 | 潛在價值大，但品質改善尚未證明；Q1才啟動 |
| 單一來源的外部證據連結 | 4 | 4 | 3 | 4 | 3 | 74 | 先解具體資訊缺口，不做全網聚合 |
| 盤後重要變化通知 | 3 | 4 | 2 | 3 | 3 | 61 | 降低漏看，但價值依使用習慣而定 |
| 單產業供應鏈／領先指標 | 4 | 2 | 4 | 2 | 2 | 60 | 研究深度可能提升，資料關係維護較重 |
| 全面 UI／裝置矩陣 | 2 | 3 | 1 | 2 | 2 | 41 | 只修真實阻礙；不能以大矩陣拖慢上線 |
| 社群／Podcast／情緒資料 | 2 | 2 | 2 | 2 | 1 | 38 | 可用訊號和維護成本尚未證實 |
| 完整 DQ／歷史PIT 平台 | 2 | 2 | 1 | 1 | 1 | 31 | 與研究精簡方向不符 |
| Production HA／多區與新平台 | 1 | 2 | 1 | 1 | 1 | 25 | 目前缺具體需求；新成本與權限面較大 |

功能導致的資料安全或答案正確性 bug 不參與上述可選功能排名，歸原任務必要修正。研究資料整理雖高分，也不能先於具體實驗自行擴建。

敏感性：若個人很少保存筆記，PLAN-01 的直接幫助會降低；若每天因漏看重大變化而錯過研究更新，PLAN-03 可提高優先級。若模型結果明顯不可用，應在 Q1 優先做 PLAN-05，而非繼續堆資訊。開工時用實際3～5個使用場景重排即可，不新增長期觀測工程。

## 5. 兩個可行架構方案

| 維度 | A：既有 Janus 內增量（推薦） | B：獨立研究擴充服務 |
|---|---|---|
| 業務價值 | 直接串既有持股、筆記、報告 | 研究功能可獨立迭代 |
| 架構 | 既有 API／Private 層／Mart Job／PG／GCS | 新 Cloud Run Service／Job 與明確 API |
| 技術複雜度 | 中低；先查重用點 | 中高；跨服務契約、狀態與快取 |
| 交付速度 | 較快，小切片 | 前置較多 |
| Cloud Run | 不增加新部署單位；長工作沿既有背景路徑 | 可獨立調整負載；需新增容量決策 |
| DB／網路 | 有界查詢；不增連線池上限 | 新連線池與跨服務資料流 |
| 安全面 | 沿 Owner 隔離與現有認證 | 增服務身分與 IAM 面 |
| 成本 | 低至中，取決於來源與按需 LLM 用量 | 中，新增服務、呼叫與維護 |
| 維運 | 現有監測與 Release | 額外部署、告警、版本相容 |
| 長期維護 | 控制模組界線，避免巨型 API | 分工清楚但多系統同步 |
| 故障隔離 | 區塊 partial、功能開關與舊產品回復 | 部署隔離較強，資料一致性較複雜 |
| 可逆性 | 關閉新功能，保留使用者資料 | 需處理服務退役及資料搬移 |
| 與目前規模適配 | 高 | 只有獨立負載／團隊需求明確才值得 |

**選 A。** 當實測證明既有 Job／API 無法在原有資源界限內處理目標工作，且獨立擴展確實有價值、費用與權限已核准，才重新評估 B。此時不能只靠加大 instance 數；先核對最大 instance × pool 大小及其他工作共用的 DB 連線需求。

共通設定方向：沿既有區域、Service／Job、SA、ingress、連線池與部署程序；不預設增加 CPU／RAM／min instances／max instances。查詢限 owner／symbol／期間／筆數；外部抓取及 LLM 不放同步 GET 路徑；重試與 timeout 受原有工作界限控制。每日業務仍由唯一兩小時總控判斷 due，不新增 GitHub 業務 cron、逐股 Job、Pub/Sub、Cloud Tasks、Vector DB 或 Graph DB。

成本控管：先設定每次標的／來源／文件／token 上限、同輸入快取及失敗停止條件，再上線；價格未知不填月費承諾。API 只回安全摘要，不記錄 token 或私人筆記原文到一般 logs。按需 CEO 沿既有 Gateway，不因有新文章自動每天呼叫 LLM。

## 6. 五個可上線階段的詳細規格

下列數量是**建議初版工作上限**，不是現有 runtime 設定；設計時可依直接證據修正。每期都先做最小契約差異，再實作→部署前測試→部署→有界 live 驗收。不能等第五期才讓第一期上線。

### PLAN-01｜研究追蹤：保留「當初為什麼關注」

**成果**：使用者能在既有筆記／個股入口看到本人的研究假設、支持與反證、下次要確認的事，以及目前報告和上次的關鍵差異。

- 重用：既有筆記、Watchlist、A-CHANGE observation、SEQ-07 Owner history／報告。先比對既有欄位，已有等價能力直接沿用。
- 增量：私人 thesis 與觀察／報告 reference 關聯；待確認、支持、反證、待更新、手動結案等研究狀態。這與公開 observation 狀態分開，不複製 A-CHANGE 引擎。
- 最小邏輯欄位（提案，非現有 schema）：owner、symbol、thesis_id、文字、evidence_refs、report_ref、觀察條件、使用者狀態、版本、updated_at。實際命名沿現有契約。
- 事實可自動提示「新增證據／待複查」，不能由 LLM 自動將私人假設定為正確或關閉。缺資料不能判為反證。
- 報告差異用結構化數值／文字模板比較；同輸入不生新差異。舊報告缺失顯示無比較基準，不回補造史。
- 私人研究不進公開 Mart／公開模型 X；公開報告在同股票同版本下保持相同。
- 更新：使用者編輯即保存；報告更新時沿既有背景流程更新關聯。沒有新資料不重跑 LLM。
- 有界驗收設計：3檔股票、每檔2個假設，涵蓋新資料、同資料重跑、缺值、撤回關注、不同 owner 拒絕讀取；能追到被引用的報告版本。這是未來測試計畫，本輪未執行。
- 產品成功判準：可在一個既有個股／筆記流程回答「原假設、最新證據、下一個觀察點」，無需跨多份報告人工找；若只是重複既有筆記顯示，縮減或取消增量。
- 回復：關閉新關聯顯示／回復上一服務版本，既有筆記和新私人資料保留，不能用 rollback 刪除使用者內容。
- 不含：新 Chat、通用 agent、提醒排程、社群、模型調校、額外研究 Mart 平台。MCP 只有確有讀取需要且原 scope 足夠才在後續子切片接唯讀，不新增寫入工具。

### PLAN-02｜私人曝險與唯讀情境

**成果**：在交易前以假設數量／價格比較交易後現金與個股權重，清楚知道是試算，不改真實交易。

- 重用：既有 backend trade calculation、費稅、ledger checkpoint、Private snapshot；不由 Flutter 產 authoritative 金額。
- 第一版僅個股集中度、現金影響、買／賣單一假設情境；有可信產業 mapping 才補產業集中度。
- 輸入：同 owner 的版本、估值日、現金、持股、假設交易；輸出：before／after、預估費稅與收付、剩餘現金／股數、可用總額及缺值原因。
- 權重分母採同一估值時點的完整有效持股市值；若宣稱含現金總資產，現金也必須完整。不能混用部分已知持股製造100%權重。
- 價格過期／缺值、現金來源不全、超賣、負數及版本改變需明示或拒絕相依結果；可保留仍有效的股數與計算項，不整頁失效。
- 初版不做共變異數／組合 VaR／最佳化權重，避免把單股 Risk 年化波動直接相加為組合風險；不輸出買賣指令。
- 更新：使用者按需試算；試算不建立交易、不觸發全市場重算、不抓分鐘資料。
- 有界驗收：買進、部分賣出、現金不足、缺價、版本衝突、跨 owner；成功及失敗請求後 ledger 筆數與版本不變。
- 上線界線：完整資料可比較；不完整資料有明確 unavailable。無法證完整分母則只發布有效現金／股數試算，不能假稱曝險已完成。
- 回復：關閉情境入口，原記帳／報價保持原行為；沒有要反向沖銷的真交易。

### PLAN-03｜精選外部資訊與可選盤後摘要

**成果**：使用者看到「與我研究標的有關、值得重新檢視假設的資訊」，每則附可開啟來源與日期；不是另一個全市場新聞網站。

分成兩個可單獨發布子切片：**03A 站內證據卡是核心；03B 單一站外摘要只有使用者另行選管道並授權後做。** 03B 失敗或未啟動不阻塞 03A。

- 03A 首批最多10個目標股；先沿既有公司公告／IR，再選一個確實補缺的合法來源。公司／symbol 對映不確定時不自動掛名。
- 最小欄位：來源 URL／標題、symbol、發布日（未知保留未知）、抓取日、內容修訂識別、摘要、來源類型、引用；保留政策只按直接必要的權利與成本設定。
- 相同內容轉載合併，來源更正標修訂；新聞敘述與 canonical 數字分開，不從文章中的模糊數字覆寫財務值。
- 首版以來源連結、可允許短摘錄與既有事實模板為主；需要長文解讀時由使用者按需啟動既有 CEO／Gateway。
- 券商報告／consensus／目標價只在存在可用權利與資料契約後考慮。未取得來源時明列 unavailable，不用網路零散價格拼成「市場共識」。不得把本人的目標價、外部券商目標價、Valuation 估值區間混為一欄。
- 03B 只做盤後重大研究變化摘要，預設關閉。沿唯一 Controller，於既有資料完成後最多每日一則；若當次流程只有翌日資料則標示真實資料日，不承諾收盤即時到達。
- 03B 必須有明確 opt-in／取消、安靜時段、事件去重、頻率上限、有限重試與 delivery status。供應商 accepted 不等於使用者已讀；未知送達不得盲目重送。
- 建議冪等鍵含 owner、channel、資料日與內容版本；通知不含私人交易數量／現金，導回已登入頁面。新通道費用／權限／OAuth 依當次核准處理。
- 有界驗收：10則文件含轉載、更正、時間未知、錯 symbol、抓取失敗；通知另驗未訂閱、取消、安靜時段、重跑、未知送達。以測試收件者受控驗證，不向其他人任意發送。
- 回復：停來源 adapter／通知開關，站內保留已取得有效證據與原報告；不刪原始私人資料。
- 不含：盤中預警、tick／串流、全網爬蟲、社群情緒、無限 RSS／Podcast、付費共識平台、第二排程。

### PLAN-04｜單產業脈絡與領先指標

**成果**：對一個實際關注產業顯示公司／產品關聯及最多兩個營運背景指標，說明它們與既有持股研究的關係和限制。

- 先由現有持股／觀察股選最有研究需求的一個產業，不先猜一定是半導體；至多10家公司、20條有來源的關係、兩類指標。
- 候選順序：既有公司公告與 IR → 可解釋的經濟部外銷訂單／工業生產 → 特定海外需求公司 SEC 文件或海關分類。不是一次全部收取。
- 每個選擇需能回答具體問題，如需求變化是否與個股營收方向一致；總體產業成長不能直接推成某公司受惠幅度。
- 公司關係邏輯欄位：entity、relationship、對方、適用期間／查閱日、來源、confirmed／inferred／unknown。LLM 猜測的供應關係只可標研究假設，不升級確定事實。
- 使用既有 PG／artifact 的簡單關係清單即可，不建 graph engine。只有被採用的可取得指標才接既有 Stage→Core→分析 artifact，不做全面 ontology。
- 更新依來源發布節奏／人工研究變動；不每天重抓月資料，不回填虛構公告日。
- 初版只作研究背景卡，不能變第五模型、不能改四模型 X／label、不能直接產買賣訊號。之後若想當模型因子，另走 PLAN-05 的實驗。
- 有界驗收：每條公開關係可點來源，推論與事實分開；指標單位／期間正確、缺一期可表達、相同內容重跑不新增；最多5個真實研究問題示範用途。
- 停止條件：無可維護來源或不足以改善問題解讀，交付研究結論後暫緩，不為了完成階段硬建圖譜。TrendForce 等付費候選保留至有具體預算與增益假設。
- 回復：關閉產業區塊／增量 adapter，原四模型與私人資料不受影響。

### PLAN-05｜2027 Q1 四模型改善，按角色發布

**成果**：每次只改善一個既有角色；若沒有可靠改善，保留目前正式模型，仍可將有界實驗標為研究完成。不得聲稱一定有四次模型升級。

- 固定次序沿 Parking Lot：Quant → Risk → Fundamental → Valuation。各角色「資料整理＋實驗＋有效性結論＋是否替換」一個完整切片，不等四個全部做完才發布。
- 05A Quant：先確認目前 artifact 真實 label 是什麼，再選相應評估；回歸、排名、分類指標不可混用。固定現有 baseline／時間切分，先驗一個因子組或方法假設，不無限制掃參數。
- 05B Risk：沿同套 Risk 模型流程；八／十二等席位以實際 artifact schema 判斷。未來20日年化波動是波動預測，不改稱跌幅／報酬機率；改善比較用適用誤差與相同 baseline。
- 05C Fundamental：沿「公告當月營收後預測下月營收 YoY 百分點」的實際契約先核對；比較季節性／持平等適用 baseline，處理尺度、缺月與 train-only 前處理；不能只看流程 PASS。
- 05D Valuation：在同一 Valuation 角色內改善 PE／PB／必要因子及 VAL-MIN30 限制；唯一估值卡保留確定性情境與模型輸出區別。不同會計比率不得互換，虧損 PE／負淨值等依口徑處理。
- 每角色先列 artifact 路徑、feature_order／單位、X/Y、split、baseline、evaluation；只補本次必要缺口。研究輸入另存既有研究空間，不依賴被清理的歷史 Core snapshot。
- 同日股票按日期群組切分，label 跨界需處理；只在 train fit 前處理。已被反覆看的 test 誠實標 validation，不偽稱新獨立 OOS；不追加新20日 cohort等待作前置。
- 實驗前定主要指標、可接受退步範圍、基準、最多候選數與停止條件；具體數值依現存評估設定，不在不知道標籤與尺度時臆造。
- 初版工作上限：每角色一個假設、最多三組候選；沒改善停止，保存失敗結果。已完成 v25／v26 不為補流程重跑。
- 研究 artifact 完成不自動改 Registry。使用者指定替換該角色後，沿既有 SHA／model schema／必要 serving parity、Release、rollback及真實推論路徑單角色發布。
- 上線驗收：實際模型可載入、同版特徵順序與公式一致、選定真實個股輸出和 UI 語意一致、其他三角色版本不被改動。局部缺值按角色退化，不能把規則輸出冒充新 ML。
- 回復：Registry／artifact 指向上一可用版本，維持同一 canonical 角色與估值卡；保留可回復的實際模型檔。

### 7.1 風險與具體控制

| 風險 | 機率／影響（規劃估計） | 控制 |
|---|---|---|
| 與 A-CHANGE／SEQ-07 重複開發 | 高／中 | 設計先出既有／增量差異表；只有缺口進程式 |

### 7.2 批准界線

一般既有 dev 的後續已授權工程可依專案規則閉環，不逐步要求確認。需新的使用者決定只包括：尚未啟動的本規劃階段、新付費／增費、重大 IAM／prod、不可逆資料刪除及本人 OAuth／MFA。通知需明確選定收件範圍與管道；模型研究結果替換正式版本依當次啟動範圍確認，不把文件交付當替換授權。

本輪沒有新 GCP resource 規格；既有區域／身分／pool／timeout 以開工當下版本化配置為準。若未來須新增 migration，採相容新增、保留舊 reader、回復不刪私人資料；不得以刪表配合新 UI。

### 8.2 各階段通用四階段指示
