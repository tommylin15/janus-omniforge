# 持股優先：報價、交易損益與分階段交付

更新：2026-10-13。狀態：已確認需求；實作／驗收狀態只見 [TODO](../todo.md)／[status](../status.md)。

## 1. 開發順序與範圍

1. **持股完整可用**：上市／上櫃全個股官方 EOD、快速持股報價、交易前試算、成交入帳後即時更新股數／成本／交易損益、手動正式重算及持股頁／首屏效能。
2. **個股通用圖表及四頁整合**：先可靠價量，再依合格資料提供營收、EPS、估值、法人與事件；沿用 [四頁 UI](../ui/visual-first-four-pages.md)，不依賴五分析師或 CEO 才能使用。
3. **有效模型後的分析報告**：五分析師逐一通過品質與 publication gate 後，才建置對使用者呈現的完整整合分析報告。既有研究／CEO 工作保留後置，不當前兩項發布前置，也不宣稱模型能保證精準預測。

本輪文件整理不啟動部署或訓練。後續工程先完成第 1、2 項整套相依改動，再集中驗收，不逐頁逐 API 上線；安全／migration 前置檢查與必要開發測試保留。模型研究有獨立驗收，避免「等報告才能用持股、等產品才做模型」的循環依賴。

## 2. 快速報價的完整含義

- 全市場 EOD 依官方有效名冊定義預期股票，TWSE／TPEx 分市場統計預期、成功、停牌／無成交、缺失、拒收及最後交易日。不能用本次抓到的列數當預期數而宣稱 100%。新上市／下市需有生效日期；缺行情不能抹掉已持有股票。
- 全市場官方批次 → Stage／Core／provenance → bounded PostgreSQL serving；交易加入持股後可直接取價，不等研究或週末換榜，也不在頁面逐檔重抓全市場。ETF 沿既有授權路徑保留，不因個股擴大而消失。
- 「全抓」指全股票覆蓋與每日增量，並非每次重抓全部歷史或全市場分鐘輪詢。retention、來源授權與既有資源限制不變。
- 首屏先回本人最新 operational positions 和已持久化合法報價，再非阻塞更新；單檔缺價不阻塞其他持股、交易或成本。backend 回資料日、來源、狀態、ledger version；Flutter 不拼接不同 owner／版本的結果。
- 盤中需求、TTL、節流與 EOD 交接依 [報價契約](quotes-and-broker-profile.md)。無授權 TPEx 盤中來源時明示「正式收盤價／日期」，不能稱即時報價；抓取時間不等於成交時間。
- 更新失敗保留最後成功值並明示過期／失敗；只有快取不能聲稱新鮮。離頁／背景停止輪詢，切換帳號清除私人快取；舊回應不得蓋過新交易或新股票。

## 3. 三種損益不能混成同一個等待狀態

| 操作 | 必須立即可用 | 正式性／後續處理 |
|---|---|---|
| 交易前試算 | 輸入買賣、股數、價格、費用及稅額；backend 回預估淨收付、賣出預估已實現、剩餘股數／成本 | 唯讀，不寫 ledger／Mart、不代表已成交；未知費稅明示，不能默認 0 |
| 記錄實際成交 | append-only 入帳成功後回新的 ledger version、股數／成本、該筆交易損益 | 同一 deterministic 成本規則；缺市場報價不能阻止計算已知成交的已實現損益。正式歷史報表未追上時另標 pending |
| 更新股價／重算報表 | 更新股價更新 operational 未實現估值；正式重算建立可查 request | 兩個獨立操作。Private Mart 必須有 terminal status 與 exact checkpoint；Job 啟動／container SUCCESS 不等於重算成功 |

沿用 `MOVING_AVERAGE` 成本法與 Decimal、既有貨幣精度／四捨五入規則，不新增成本法切換。買入成本包括實付費稅；賣出損益＝成交淨收入－按既有移動平均法釋出的成本。未實現估值與「假設現在賣出扣費稅後的損益」分名，不暗扣未發生費用。股利、股票股利、更正、作廢、補登依既有 ledger 重播語意處理，不悄悄改變年度報表定義。

試算與入帳共用 backend 計算規則；可重用既有實作，缺 API 才補最小 owner-scoped endpoint。金額規則、broker profile version、ledger version 與輸入快照可追溯。正式送出時重驗版本、股數、費稅與冪等 key，過期試算重新取得，不能把舊結果直接存為事實。不得自行假定券商已成交或新增自動下單。

驗證至少涵蓋：新買入原 500 池外的上市／上櫃股票、加碼、部分／全部賣出、零股、合法零費用與未知費用、股利、更正／作廢、歷史補登、版本衝突、重送及超額賣出拒絕。損益以 backend／Private Mart 可核對；Flutter 只呈現。缺價格或缺成本須區分，合法 0 與 unknown 不混用。

## 4. 速度目標與量測

下列是本輪工程驗收目標，不是已測成績；未達時記錄瓶頸與 gap，不以延長 timeout 通過。

| 使用情境 | 目標 |
|---|---|
| 同帳號暖進持股頁 | 可用股數／成本／持久化報價首屏 P95 ≤2 秒 |
| 冷進持股頁／今日首屏 | 可用主資訊 P95 ≤5 秒；深度分析不參與 critical path |
| 交易前試算（有效輸入至結果） | 暖路徑 P95 ≤500 ms；輸入 debounce 另記 |
| 成交保存到新版股數／成本／該筆損益可見 | 暖路徑 P95 ≤2 秒；正式報表異步進度分開量測 |

真實 dev 固定 source SHA、裝置／網路／viewport；分開記端到端與 API、冷暖路徑、cache hit、有效樣本數、P50／P95、失敗率、報價 age。每個暖情境至少 30 次有界觀測；冷樣本不足時逐筆列出，不冒稱穩定 P95，不為湊樣本任意重啟共用服務。真實交易量測使用受控測試 owner／既有合法測試路徑，不往本人帳本製造測試交易。timeout／失敗不能從統計悄悄刪除。

## 5. 模型與報告啟用條件

沿 [五分析師契約](specialist-engines.md) 逐角色預先固定用途、基準、樣本／期限、時間切分 OOS、成本與不確定性、資料來源及 PIT 限制、版本／漂移／回復方式；不可見結果後降低標準。有效不必然使用 ML，但必須有符合該用途的驗證證據。訓練完成或規則能輸出不等於有效。

前兩階段只呈現官方事實、通用圖表和中性資料說明；未驗證健康分數、買賣暗示、目標價、勝率及整合摘要不放主畫面。研究狀態可在收合區顯示，不以五張空卡占首屏。五者有效且同時點 artifact、publication、freshness、引用完整後才啟用整合報告；過期／缺失則退回圖表並說明。既有 CEO artifact 保留歷史，頁面不自動呼叫 LLM，費用／capability／quota 約束不變。
