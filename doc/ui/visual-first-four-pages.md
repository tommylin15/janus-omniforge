## 1. 使用者目標與權威

四張 [Final Visual Contract PNG](reference/user-app-final/README.md) 是最低視覺基礎，不是圖表或資訊架構的上限。2026-10-11 使用者重新確認：**每頁唯一主訊息，先看圖、顏色、關鍵大數字，再看白話解釋和進階數據**；若舊圖片／舊版 UI 文字排列牴觸本次補強，以本文件與同步修訂的 [User App 契約](user-app.md) 為準。原四張 PNG 保持 bytes 不變，圖片中的股票、價格、PnL、日期、圖線、logo、研究文案皆為示意，不能當成真實已部署資料。

任何 UI 順序不得凌駕官方資料、source authorization、PIT／available-at、provenance、public/private owner 隔離、canonical number、partial／stale／missing／blocked 或模型 publication gate。未驗證的 ML 機率、研究分數、分類可信度不能包裝成獲利勝率；頁面載入不自動呼叫 CEO／LLM。

## 2. 四頁定位及資訊層級

| 頁 | 主要問題 | 主 Hero／強調數字 | 次級視覺與下鑽 |
|---|---|---|---|
| 今日 | 今天**與我**最有關的持股／關注／市場變化是什麼？ | 最多三則本人相關事實變化；無則TAIEX，資產為緊湊摘要 | 真實短趨勢、最多三件事、產業／候選入口 |
| 關注 | 我追的哪些股票現在有異動？ | 每檔最新價與漲跌，已持有／目標價／待追蹤狀態 | 有證據才顯示異動摘要、短趨勢；直達個股 |
| 記帳／持股 | 我的持股市值和賺賠怎麼變？ | **持股市值**、未實現損益及報酬、估值日期 | 損益貢獻 mini bars；歷史趨勢放報表 |
| 個股 | 這檔價格、成長、估值與風險在哪？ | 現價／漲跌、本人持股、三行事實與短價量圖 | 通用圖表捷徑、籌碼／事件；模型有效後才加報告 |

### 今日：與我有關的新變化（2026-10-16 定版）

首版依序為：
1. **我的資產短摘要**：共用owner持股snapshot，現金與參考總資產、持股變動一行，點擊進持股。這是緊湊摘要，不再加一張巨大Hero；未登入不查私人資料，無持股／現金未設定不造0，摘要失敗不阻擋市場區。
2. **今天值得看**：唯一主要訊息區，最多三則「公司／變化＋數據依據＋有證據才列的疑點」，各有查看營收／獲利／公告等直接入口。排序採本人持股、本人關注優先，再依已定義異動類別與來源時間，tie以symbol固定；不另造預測分數。只用可核對的已持久化事實。
3. **市場現在的位置**：TAIEX小趨勢與當日變動，市場廣度只有既有合格資料才加。無個人異動時，此區升為主訊息，顯示「目前沒有新的重要變化」；抓取失敗則顯「異動資料暫未更新」，兩者不可混同。
4. **追蹤有進展嗎**：後續在同頁接既有股票筆記／待追蹤與最近資料更新，預設收合；無追蹤不放空卡。
5. **值得進一步研究**：後置最多三個有證據候選、預設收合，沿既有screening／D07有效性邊界；不是推薦排行榜，不為填滿而造內容。

同一公告或同一期指標修訂以既有event ID／symbol+metric+period+source version去重，變更才更新，不能每天改寫同一訊息冒充新資訊。不同資料期可並列，但各自標期別，不拼成同日綜合判斷。首版以「最近更新」表達，不聲稱「自上次查看」，不新建已讀紀錄或通知系統。

### 關注：動態狀態不是靜態報價清單

搜尋名稱／代號及關注數／50、全上市櫃新增資格說明可見，取消原 500 限制。股票卡先大字現價／漲跌，次要名稱代號、日期、已持有／未持有、目標價、待追蹤筆記與「離榜保留」；依合法 persisted 價格／事件做異動摘要，沒有可靠規則時不造異動排名。目標價屬使用者設定，不是模型推薦。待追蹤 chip 不代表已啟用通知。stale／missing 股票不因空值從清單消失，owner isolation 與加入／刪除仍由 backend 決定。

### 記帳／持股：資產變化先於記帳細項

次導航固定 **持股／紀錄／報表／筆記**，四格摘要只在持股；依User App最新持股契約，總資產主區呈現現金與現金＋持股市值，其餘PnL與日期分主次；每檔維持1–2行。未驗證涵蓋現金與其他資產前，不能稱為「總資產」。持股卡突出每檔損益金額／比例、股數、現價／均價；依同一 authenticated owner、同一 Private Mart checkpoint 的貢獻額畫正負條，不能 Flutter 重算正式損益。

報表以歷史市值／損益趨勢為主圖，但必須存在至少兩筆真正可比的已發布歷史估值；不能用短時間內多次即時報價畫假歷史資產曲線。紀錄以已實現損益為重點，現金流≠損益；新增／更正／作廢仍走 ledger append-only，待 Private Mart 更新時清楚顯示 pending／checkpoint mismatch。

### 個股：讀懂變化、查看證據、留下驗證點（2026-10-16 定版）

1. **股價與我的持股**：現價／漲跌／時間，持有者顯成本與損益；不變動既有金額與Owner契約。
2. **三行研究重點**：營運變化／估值參考／價格風險，各至多一行。只用deterministic可核對事實，直接點入對應圖與期間；缺同比仍顯營收、缺歷史位階仍顯PE/PB、有價格但無風險窗口就不造風險結論。這不是CEO或綜合研究評分，不用等五模型有效；沒有可用事實的行給簡短原因，不堆三張空卡。
3. **一個主要圖表區**：預設短價量，切價格／營收／獲利／估值／法人／事件；價格預覽就是同一主圖，禁止重複畫兩張。最新值／單位／期別先行，點圖看值，可放大；每圖可有一則可重算事實短句。已有公告日期可在價格圖標記，僅表示同時發生，不宣稱因果。
4. **支持與疑點**：各最多兩項可驗算事實及其來源連結，例如營收增加但毛利率下降；無足夠比較資料就不硬湊。支持的是待研究線索，不直接斷言買進／合理價；需要模型推論的結論留D07/D08。
5. **下一個驗證點／筆記**：沿既有筆記與pending-follow-up，顯示研究理由、要觀察的指標、資料日期；可從圖表建立筆記。首版沒有可靠未來公告日時顯「下次資料更新後確認」，不猜日期。自動條件判定與自上次查看差異是後續候選，不能默默新增排程／狀態系統。
6. **深入研究**：來源／口徑、五角色狀態、情境與手動CEO按原capability與模型gate收合顯示；不自動執行LLM，不顯未校準勝率／健康分。

首版範圍為1–4及既有筆記可直接重用部分；5的進階自動化、首頁4–5與高階研究不成為本次發布必要條件。短資料、單值、partial的可用規則見 [三層交付](visual-first-delivery.md)。

## 3. 圖表語意／視覺元件規範

- 首屏只能有一個主 Hero。主 KPI 明顯大於次級數字；台股紅漲／紅獲利、綠跌／綠虧損，同時加箭頭、正負號／文字，不用單純顏色作含義。未知與 0 用中性色。teal/cyan 是品牌與選擇，不表示績效。
- 每張圖要有**名稱、單位、橫軸日期、期間選擇、可點觸提示、最後資料日、來源／狀態**；無足夠點數、不同期間／不連續缺口不可畫連續趨勢或估值分位。空值不得補 0、不得改用非授權來源隱性補圖。
- 價量：OHLCV／量／MA5/20/60 的計算版本，交易日和公司行動；未還原與還原價不混線。
- 月營收：正式逐月序列、YoY 比較基期；不能直接把重大訊息內單筆敘述湊成完整圖。
- 季 EPS／淨利：同一季／合併口徑、單季與累季、股本基礎、歷史更正與 available-at 可比較才畫。
- PE／PB／殖利率：合法 null、虧損 PE 不造值、0 殖利率有效；歷史分位必標期間與有效樣本數，不等於 DCF。
- 法人：外資／投信／自營商按日同單位買賣超、累積圖，某類缺失明示 partial。
- 事件：event ID 去重、公告發布／首次觀測／生效日期、版本；事件方向不明不塗成利多或利空。
- 資產：持股市值與真正「總資產」分名，貢獻分布／歷史走勢皆由同一 owner 的 backend／Private Mart aggregation 提供。
- 390×844 級手機、放大文字、鍵盤／讀屏、觸控圖點仍不 overflow。各區塊獨立 loading／empty／error／partial／stale，主資訊不因深度分析失敗而消失。

## 3.1 初期通用圖表選型（2026-10-13）

先完成 [持股／交易損益與效能](../spec/holdings-first.md)，再完成本節。初期一次只顯示一張主圖；切換指標按需讀取，不把六張大圖一次堆上手機。價格預設近 3 個月，提供 1／3／6／12 月；來源不足時顯示實際範圍，不拉長假線。財報用實際月份／季度，不套用日線期間。

| 用途 | 預設圖形 | 最少必要資訊 |
|---|---|---|
| 持股快速判讀 | 市值大數字、每檔損益正負水平條 | 現價／成本、損益、日期；同版本才比較，不依賴歷史圖才可交易 |
| 個股價量 | 收盤折線＋下方成交量柱，共用日期軸；可切日 K | 元／股、成交量單位、最後有效日；MA20 可選且預設關閉，不堆 MA／MACD／RSI |
| 月營收 | 月份長條 | 金額；YoY 放選中點提示，初期不疊雙 Y 軸 |
| 季 EPS | 單季長條，保留負值與零線 | 元／股、季度與合併口徑；累計資料未可靠轉換不能當單季 |
| PE／PB／殖利率 | 一次一項折線 | 倍／% 分開，不用同一刻度混畫；不預設分位／估值河流 |
| 三大法人 | 一次一類按日正負柱；可切外資／投信／自營商 | 淨買賣超、股或張固定單位、零線；不是股價預測 |
| 公司事件 | 短時間軸 | 公告／生效日期、標題及來源；方向不明維持中性 |

沿用白卡、淺底、teal 操作色、紅漲綠跌及文字正負號。主圖手機高度約 200–240 邏輯 px，可隨字級增高；一般說明至少 14、主數字約 28–32，仍遵守既有對比與觸控規格。軸標保持少量可讀，長名稱換行，提示框不能遮掉主要數字。長條以零為基線；價格折線可縮放但需顯示軸值。禁止 3D、儀表盤、雷達健康圖及無意義漸層裝飾。資料表／讀屏摘要提供圖形的等價資訊。

參考查閱於 2026-10-13：

- [TradingView 圖表分類](https://www.tradingview.com/support/folders/43000547460/)：提供折線、K 線、面積與柱狀等常見形式；本案只取必要基本圖形。
- [TradingView baseline 說明](https://www.tradingview.com/support/solutions/43000690232-baseline-charts-explained/)：線與基準有助讀取變化；Janus 若加參照線必須明示前收或所選期間起點，不將視窗中線冒充成本／損益。
- [Fidelity Open Positions](https://www.fidelity.com/webcontent/ap002390-mlo-content/18.02/help/learn_open_positions.shtml)：參考持股與已平倉損益的區分、金額／百分比閱讀方式；不引用其稅務或成本法作台股規則。

上述選型是 Janus 的簡化設計判斷，不是對方對本專案的建議，不需要採用外部圖表 SDK、付費資料或複製其圖像。

## 5. AI 必須照做的版面規格（2026-10-16）

本節是實作target，不是已完成截圖。既有Material 3／teal色系與共用theme tokens優先，不新增UI框架。下列尺寸以logical px為準；文字放大時容器自動增高，禁止固定高度裁字。四張舊PNG作色彩／元件基線，區塊順序以本節為準；不照搬舊健康雷達／高持股卡。完整數值均取API，不使用設計示例填資料。

### 首頁手機：由上而下的實際長相

| 區塊 | 版面／內容 | 動作 |
|---|---|---|
| 頁首 | 左「今日」，右既有刷新圖示（若現有）；下方小字資料日期，不新增第二排大型標題 | 刷新沿既有節流，不建立全市場即時抓取 |
| 資產短摘要 | 一張低矮卡，左右兩欄「現金」「參考總資產」，數字24，萬元一位；下方一行持股變動／涵蓋狀態；基準高度約104–128，可隨字級增加 | 整卡或右下「查看持股 ›」進持股；未設定顯「設定現金」進既有設定 |

| 市場位置 | TAIEX名稱與最新指數左右同列；漲跌次行；下方趨勢圖高約120；資料期顯圖下 | 點擊進現有市場詳情（有capability才可）；不新建無效入口 |
| 後續追蹤 | 收合列「我的追蹤」＋既有筆記數；展開短列表 | 點入該股筆記；首版無需新監控 |
| 後續候選 | 收合列「值得研究」，最多三檔與一行來源理由 | 點個股；無合格候選隱藏，不顯空排行榜 |

首屏優先看得到資產摘要及至少第一則重要變化；不硬縮字以塞下三列。重要變化區是主訊息，不另外加Hero重複同一則。無異動顯一行「目前沒有新的重要變化」，TAIEX自然上移；資料失敗改「異動資料暫未更新」＋小重試，不能假稱無變化。
桌面左欄約2/3放重要變化與市場圖，右欄約1/3放資產短摘要與收合追蹤；以CSS／Flutter響應式排列，不另開一套資料請求。

### 圖表／狀態必畫的樣式

- 價格：折線＋成交量，可切既有K線；營收：月柱，金額／YoY小切換，不疊雙Y軸；EPS：正負柱＋零線；PE/PB：一次一條；法人：正負柱；事件：日期＋短標題的直向列表。
- 一點：大數字／單柱＋期別，不拉線；短期間：標實際起訖，不提供會誤導的「五年」標籤。缺月留斷點，不補0。
- 載入：僅該卡骨架；刷新：原值保留加小進度；失敗：卡內一行原因與「重試」；已有值不因次圖失敗清空。
- 有營收無YoY：保留金額柱，YoY選項旁「缺同比基期」；只有累計EPS：標明累計期，不標單季；虧損PE：顯「不適用」，PB有值照常。
- 來源日期未知到不能辨認所屬期：該值不畫；只缺精確首次發布時刻而資料期明確，當期圖仍可用。
- 圖表讀屏／等價表格顯示日期、單位與值；390px、200%文字放大下允許卡變高，無遮蓋、無水平頁面溢出。
