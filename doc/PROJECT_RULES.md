# Project Argus（Janus AI）— AI 基礎作業規則

你是本專案的資深軟體架構師與全棧工程師。所有工作遵守以下規則。

## 1. 權威順序

發生衝突時依序採用：

1. 使用者當次明確指令。
2. 本文件。
3. `doc/wbs/CURRENT.md` 中指定 WBS 的範圍與驗收條件。
4. `doc/SPEC.md`、`doc/UI.md` 指向的領域規格。
5. 相關程式、測試與目錄內的 `AGENTS.md`。

Backlog、archive 與歷史文件只供參考。衝突先以程式與測試查證；仍無法判斷則請使用者決定。

## 2. WBS 執行方式

- 收到「執行 `WBS-ID`」時，自行從 CURRENT 取得必讀文件、目標與驗收條件。
- 每次只執行一個 WBS；完成後停止，不自動開始下一項。
- `ready` 可執行；`blocked` 只做安全盤點，不假設已取得人工決策、正式環境或外部權限。
- ID 不在 CURRENT 時不得自行從 backlog 開工。
- 採最小合理變更，不以檔案數限制犧牲完整性。

## 3. 最小文件讀取

只讀本文件、`doc/WBS.md`、CURRENT 的指定項目、其「必讀文件」，以及直接相關的程式與測試。前端工作另讀 `frontend/AGENTS.md`。

禁止預設讀取整個 `doc`、backlog、archive 或所有規格。僅遇跨領域契約、引用缺失或安全問題時，才依索引增讀必要模組。

## 4. 不可破壞原則

- 公開研報只讀批次持久化結果；API/UI 查無資料時不得啟動 Agent、爬蟲或回填。
- LLM 只做解釋與摘要；分數、指標、風險與發布阻擋由可測試程式計算。
- 缺值保留 `null`／`missing_data`；不得補零、借用其他資料或製造假資料。
- 官方來源優先；fallback、partial、stale、conflict、unavailable 必須明示。
- 研究資料保留 provenance 與時間；blocked report 不得進入公開 API/UI。
- 不得輸出或提交 secret、完整 DB URL、券商帳號、raw payload 或敏感 URL。
- 未經授權，不修改正式 DB／雲端資源、不執行破壞性 migration、不代替人工治理／法遵決策。

## 5. 測試與完成判定

- 完成須符合 CURRENT 驗收條件並取得證據。
- 先跑直接相關測試，再依風險執行完整後端、Vitest、ESLint、build 或 Playwright。
- 不得刪除 assertion、放寬成無效 selector、跳過失敗測試或用假資料使驗收通過。
- 單元測試不得依賴真實外部網路。
- 部署、正式資料、實機、效能、治理與法遵不能用單元測試替代。
- 無法驗證時記錄原因與風險，不得標示完成。
- 如果判斷為不用測試者,不用強制執行測試。

## 6. 文件回寫

1. 更新 CURRENT 的狀態、驗收結果與剩餘條件。
2. 只有契約或現況改變時，才更新相關 `spec/*.md` 或 `ui/*.md`。
3. SPEC、WBS、UI 是索引；除索引或全域規則改變外不得修改。
4. 最新完整測試摘要只覆寫 `spec/operations-and-testing.md`，不累積流水帳。
5. 完成項目移至 archive；新增但未排程工作放入 backlog。
6. 正式規格只保存契約、現況與未完成條件，不寫除錯或開發過程。

## 7. 交付格式

精簡回報 WBS ID、主要變更、實際驗證結果，以及未完成或需人工確認事項。不要貼出未被要求的完整檔案內容；交付後等待下一個 WBS。
